\section*{PARTE 4: RESPOSTAS TÉCNICAS EM CAMADAS}

\subsection*{Clojure / Ecossistema}
\textbf{Experiência:} 7 anos em produção. Pathom 3, Datomic, Clara Rules, Fulcro RAD.
\textbf{Insights:} Sistemas que duram têm dados como centro, não objetos. Pathom (resolvers), Datomic (schema como dado), Clara (regras como dado).

\textbf{Pathom 3:} Motor de resolução de grafos. Elimina o acoplamento 'de onde vem o dado'. O cliente pede via EQL e o motor descobre o caminho automaticamente. Útil para integrar 25+ gateways (Octopus Pay) de forma canônica.

\textbf{Datomic:} Base Datalog imutável. Escolho quando auditabilidade e evolução de schema são requisitos. \textit{as-of queries} eliminam a necessidade de tabelas de auditoria manuais.

\textbf{Clara Rules:} Motor Rete. Evita 'if-else que virou árvore'. Regras declarativas e testáveis para cálculos complexos (comissão, frete, impostos).

\textbf{Fulcro RAD:} Produtividade via atributos declarativos. Gera forms, reports e routing a partir do schema de domínio.

\textbf{Polylith:} Arquitetura de monorepo com componentes caixa-preta. Elimina acoplamento implícito. Ex: Risk Guard isolado no Ark Engine.

\textbf{XTDB:} Datalog imutável com bitemporalidade nativa (Valid Time vs Transaction Time). Essencial para eliminar \textit{lookahead bias} em trading.

\subsection*{Kafka / Mensageria}
\textbf{Gap:} Lacuna operacional, não conceitual. Padrões (offsets, consumer groups, exactly-once) implementados via Redis Streams e NATS JetStream. Interesse direto em fechar essa lacuna com Kafka.
